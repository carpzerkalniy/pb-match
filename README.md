# ПБ Мэтч · Telegram Mini App

Знакомства на мероприятиях ПБ: карточки с фотографиями и описанием, мгновенные взаимности, отдельное согласие на контакт, вход по Telegram ID. **Правка 08.10, P-026:** основная часть — карточки по одной, анимированные свайпы вправо для лайка и влево для дизлайка, с кнопками обеих реакций. Это заменяет первоначальное «только лайки» от 04.10. Привязка к участнику/CRM, поля профиля, порядок/возврат карточек и сроки отрицательной реакции уточняются.

Ориентир от 06.10: первый запуск к вечеринке 10.10.2026, основная комната постоянная сразу, есть управление участием, карточки по одной как в Tinder и независимая передача контакта конкретной паре из списка мэтчей. Поиск по имени/бейджу исключён. Допуск и сокращения разбираются отдельно; исключение CRM не принято. Дата не означает готовность приложения.

Последний выбор 08.10, **P-027:** первая постоянная комната базовая, без ключа для первого и всех последующих гостей приложения. После проверенного Telegram-входа открывается эта комната; QR может открыть приложение. Прежний общий ключ P-019 для неё отменён. Следующие комнаты будут с ключами; их объём в MVP ещё не выбран. Вход не снимает блокировку, не включает участие после профиля и не даёт согласия на контакт/связь CRM.

Работа и уведомления через Telegram-бота/Mini App; в админке фото и закрытие доступа. Бумажные мероприятия пока отдельно, без синхронизации с Mini App. 07.10 выбраны уведомления о новом мэтче и открытии контакта получателю (P-023). Тексты/частота и остальные функции админки ещё уточняются.

## Что подготовлено

По требованию P-028 добавлен настоящий браузерный прогон с touch-вводом, видео, PNG, trace и покадровыми измерениями. D02 после правок P-029/P-030 прошёл 57 проверок в Chromium на 320×568/390×844/430×932: пропорции фото, цвета реакций, нижняя навигация, длинный текст/полный просмотр и закрытие после инерции, доступность и анимация свайпов. Изображения и кадры просмотрены, независимая QA выполнена. [Порядок и повторяемый запуск](docs/VISUAL_QA.md); результаты/размещение — HANDOFF. Это эмуляция мобильного браузера, не проверка физического устройства или всего прототипа.

Локальный интерактивный макет карточек, модули проверки Telegram initData и базовых правил взаимности/раскрытия, черновик API и структура для дальнейшей реализации. Это ещё не работающее приложение для реальных гостей: нет подключённой базы, загрузки фото, привязки билетов, сохранения лайков и рассылки.

## Локальный просмотр

Из корня проекта, Python 3.11+:

```powershell
.\tools\start_preview.ps1
```

На Windows это запускает сервер отдельным скрытым процессом, проверяет страницу и использует уже работающий сервер при повторном запуске. Просмотр остаётся доступен после завершения команды; после перезагрузки компьютера запусти её снова. Логи — `outputs/preview/*.log` (игнорируются Git). Для работы сервера в текущем терминале: `python tools/dev_server.py`.

Открыть http://127.0.0.1:8765/demo.html. Оформление перенесено из сохранённого `pb-match-hub-v1.html` (см. docs/DESIGN.md). Макет использует вымышленных участников, сгенерированные портреты и хранит выбор только в памяти страницы. В профиле можно локально выбрать фото и написать описание; они не отправляются на сервер. Порт можно задать через `--port`. Сервер привязан только к loopback и не предназначен для размещения в интернете.

Галерея пользовательского пути: http://127.0.0.1:8765/scenarios/. Обновлена 07.10 под согласованный MVP: по умолчанию 21 ситуация в 6 ветках, отдельно 23 архивных/будущих варианта; после P-026/P-027 от 08.10 всего 98 шагов (U14.03 — дизлайк, U36.03 — новый гость базовой комнаты). Утверждённая основная линия по P-027 — Telegram-вход → базовая комната без ключа → профиль/участие → карточка по одной → мэтч → передача контакта из списка мэтчей. U01.02 теперь показывает подтверждённый вход без поля ключа; U36.03 — нового гостя той же базовой комнаты. U41/старые ключевые экраны сохраняют историю и относятся к будущим дополнительным комнатам. Добавлены пауза/возвращение и фото/блокировка админом. Наведение показывает экран, клик/касание открывает модалку; подробный каталог и старые Uxx-ссылки сохранены. Поиск в документе ищет ситуации, не людей. Это иллюстрации, не рабочие API. Проверка соответствия новой правке и визуальная приёмка — отдельные этапы (SCENARIO_GALLERY.md).

Проверки модуля Telegram:

```powershell
python -m unittest discover -s tests -v
```

## Дальнейшая сборка

Предлагается сохранить Python/Flask и PostgreSQL совместимыми с baza. Стек интерфейса выберем перед первой реализацией; макет написан без сборщика и зависимостей. Настоящие API, адаптер базы и воркер доставки будут добавляться после уточнения сценария и получения исходного кода существующего модуля.

Токены и подключения хранить в локальном окружении/секрет-хранилище сервера. `.env.example` содержит только названия настроек. Исторические SQL из `docs/sources` автоматически не запускаются.
