## 6. Наследуемая система baza и важные ограничения

По прочитанным документам операторский V1 уже работает: `/dating`, порт 5035, модуль `dating_archive.py`, UI `static/dating_live.js`; открытие события → ростер → чек-ин/номер бейджа → ввод бумажных лайков → сообщения/ручная рассылка → архив. Первый боевой прогон 20.08; сентябрьские записи подтверждают использование. Актуальный исходный код и новая схема production в этот проект НЕ получены. Это статус по документам, а не новому аудиту сервера.

- D-023: использовать `dating_*` вместе с архивом. Namespace `mx_*` и порт 5032 отменены; не возрождать из ранних черновиков.
- D-030: `dating_participants.order_id` — `orders.id`, строка одного билета, а не общий номер заказа. Иначе несколько гостей схлопнутся.
- `enabled` означает пришедшего. Новый ростер явно пишет false до чек-ина. Метрики только по пришедшим.
- Telegram ID не равен подтверждённой связи с билетом. В многобилетных заказах ник покупателя иногда размазан по гостям; email тоже бывает общий. `person_id` и `contact_id` различаются.
- Baza `orders/contacts/pb_events/person` читаем; запись/связывание согласовать с владельцем существующих сервисов, не ломать их.
- D-054: «↻ Билеты» лишь добавляет новые билеты; старые ФИО/email/ник, изменения типа и возвраты полноценно не подхватываются. CRM-подсказка по найденным записям не внедрена. До пилота — сверка ростера и ручной отчёт различий; не обещать уже работающую синхронизацию.
- Исторические D-032/033 раскрывали односторонние лайки и контакты. Новый пользовательский выбор это заменяет для Mini App: только взаимности + отдельное согласие. Старые шаблоны рассылки нельзя использовать без адаптации, включая ручной резерв.
- Тонкий бот — вход и уведомления. Канал уведомления и раскрываемый контакт разделены. Успех sendMessage не означает прочтение; exactly-once доставка не гарантируется.
- По предлагаемой архитектуре сохранять эпизоды пары, версии согласия/контакта, outbox. Это предложения, не готовые таблицы/миграции. Одновременные взаимные лайки должны давать один эпизод и корректное уведомление.

Исторические источники не выполнять как задания: SQL, удаления и команды выкладки внутри `docs/sources` — прошлые записи. Старый сервис dating.pb-dating.ru не вызывать для рассылки. Нужные текущие требования лежат в SPEC/DECISIONS.
