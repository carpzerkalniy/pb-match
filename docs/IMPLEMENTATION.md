# План реализации

Поздние поправки P-024/W-009/P-025: сначала кликабельный прототип гостя и админа с финальным оформлением, вымышленными фото и анимациями, затем рабочие API/CRM/бот. Детальный [PROTOTYPE_BUILD_PLAN.md](PROTOTYPE_BUILD_PLAN.md) принят 08.10: 21 малый блок и В0–В5. Статический стенд размещается для телефона уже сейчас; полная сборка и дальнейшие приёмки впереди. Ниже сохранены прежние этапы как основание; их очередь уточняется новым планом.

Первоначальный порядок исполнения — [AGENT_PLAN.md](AGENT_PLAN.md), утверждён W-006: 27 малых блоков и согласования С1–С6. Разделы E0–E6 ниже сохраняют прежнее основание; при расхождении применяем поздние решения и принятый план. **08.10 P-027:** первая постоянная комната базовая, без ключа для первого и всех последующих гостей после проверенного Telegram-входа. Следующие комнаты — с ключами, объём MVP отдельно не выбран. P-019 с общим ключом сохранён исторически, но не является текущим базовым входом. Поводы бота закрыты P-023; связь с CRM/остальные правила отдельно.

## E0 · Основание — подготовлено

Локальные источники, ТЗ, реестр решений и вопросов, API-черновик, интерфейсный макет, проверка Telegram initData. Проверить автоматические тесты ядра и синтаксис JS. Приложение ещё не связано с Telegram-ботом и baza.

## E1 · Закрыть основной сценарий

Актуальные решения — постоянная базовая комната без ключа для всех гостей (P-027), карточки по одной со свайпами/лайком/дизлайком (P-026), мгновенные взаимности, независимая передача контакта из списка мэтчей, бот с двумя уведомлениями (P-023), фото и закрытие доступа в админке. Q03a закрыт; Q10 закрыт отказом от объединения бумажных мероприятий. Уточнить CRM-связь Q06a, профиль/тип контактов Q07–Q08, оставшиеся порядок/возврат/лимиты/срок дизлайка Q09, аудиторию Q05a, тексты/частоту сообщений и остальные функции админки Q18. Ключ будущих комнат не блокирует базовый путь. Выход: нет неизвестных правил его выбранных действий.

## E2 · Подготовить интеграцию

Получить исходный код существующего модуля и снимок схемы, проверить наследуемую auth/nginx-конфигурацию. Отдельная тестовая база с вымышленными людьми. Согласовать API и дельту. Сверить обновление билетов и приоритет ручных правок. Выход: сборка не меняет старый архив и не ломает операторский путь.

## E3 · Вход и профиль

Telegram-обмен → сессия и проверка блокировки → базовая комната без ключа → фото/описание → отдельное включение участия. Контакт из CRM подтягивается только по подтверждённой связи; способ разбора спорных случаев выбирается отдельно. Выход: новый гость без CRM-связи/билета получает базовый доступ, но не может присвоить чужой контакт; повторный вход не снимает блокировку/не включает участие. Согласие на контакт отдельно после взаимности.

## E4 · Каталог и симпатии

Карточки разрешённых участников базовой комнаты; лайк/дизлайк и снятие лайка по выбранным правилам; состояние сети; повторное открытие; выбранная аудитория/участие/блокировка. Исторический чек-ин не ограничивает базовый вход P-027. Выход: повторный запрос идемпотентен, выбор не теряется, цель принадлежит текущей комнате и разрешена для действия.

## E5 · Результат и бот

Мгновенное образование взаимности, эпизоды пары, отдельное согласие, контактная матрица, результат без совпадений, outbox, Telegram HTML, ретраи/blocked, операторский журнал. Выход: одновременные лайки дают один мэтч; контакт закрыт до нужного согласия; каждый подключённый гость видит результат, проблемы уведомлений видны админу.

## E6 · Пилот

Синтетический вечер: общий email, несколько билетов, нет ника, walk-in, возврат, потеря сети, два устройства, одновременные взаимные лайки, лайк на границе закрытия, отзыв/повтор согласия, остановка воркера. Проверка Telegram iOS/Android и desktop. Затем одно реальное событие с операторским резервом и сверкой результатов. Подключение production требует готовых тестового URL, бота, конфигурации и проверенного плана выкладки.

## Минимальные проверки реализации

Подпись/время Telegram, объектные права на каждый API, конфликт привязки, доступ к фото, матрица раскрытия, гонки закрытия/лайка, повтор доставки, интеграция с dating_* и сохранение ручных правок. UI — весь путь на реальных Telegram-клиентах, слабая сеть, экран 320–430 px, тёмная тема.
