# Макеты пользовательских сценариев · 05.10

Подготовлены 05.10.2026 для отдельной локальной галереи сценариев. Главный `demo.html` не изменён. Это иллюстрации состояний, не готовые экраны подключённого Mini App.

## Основа и границы

Основа — `apps/miniapp/reference/original-hub.html` и текущий согласованный перенос, описанный в `DESIGN.md`. Сохранены #FF3E00, #FB3399, #FDEB95, #140D12, #1F141C, вертикальный градиент живой комнаты, 22px скругления, прописные заголовки, жёлтые и контурные кнопки, вкладки «Комнаты / Мэтчи / Профиль». Файл Halvar по-прежнему не предоставлен, используется исходный запасной стек Arial Black/Arial.

Оригинал содержит только хаб. Формы, карточки, результаты, согласие, помощь и ошибки — адаптации этой дизайн-системы, а не найденные исходные макеты этих экранов.

Портреты — локальные SVG-иллюстрации вымышленных гостей. `@pb_demo_guest` используется только на условном экране разрешённого обмена. Собственный `@pb_demo_self` на экране запроса согласия показывает, какое конкретное значение предлагается передать Лере (бейдж 12). Оба значения — условные примеры, а не реальные контактные данные гостей; существование и принадлежность Telegram-аккаунтов с такими именами не проверялись. Макет не открывает эти аккаунты, не запрашивает и не передаёт реальные контакты. До выбора политики согласия настоящий сервер продолжает запрещать раскрытие.

## Интерфейс для галереи

`apps/miniapp/scenarios/screens.js` экспортирует `renderScreen(step, scenario)`: чистая функция возвращает полную HTML-разметку телефона по `step.screen`. Все строки из входных данных экранируются. `screenKinds` перечисляет поддержанные виды экранов. `screens.css` полностью ограничен селектором `.journey-phone` и не меняет стили исходного макета или оболочки галереи.

Разметка отражает вид, заголовок, основной текст, подписи действий и состояние из сценария. Кнопки внутри телефона — рисунок пользовательского действия; переключение шагов выполняет оболочка галереи. Нет запросов API, записи лайков, загрузки реальных фото или хранения персональных данных.

Варианты фильтра аудитории не придуманы: экран показывает место выбора, а конкретные варианты ожидают Q05a. Обязательность полей, способ привязки, модерация, удаление и политика обмена остаются предложениями из ТЗ. Их статус должен быть виден снаружи телефона в карточке сценария. Экран контакта — пример результата при соблюдении всех будущих условий, не действующее разрешение на обмен.

## Проверка

Модуль сверён с финальными 40 сценариями и 87 шагами JSON. Все виды экранов покрыты, синтаксис JS проверен через `node --check`. Явно пустые подписи действий не заменяются кнопками по умолчанию. `policy_pending` не показывает согласие на передачу и контакты; состояние отправки лайка не изображается сохранённым; отсутствующее фото и ожидающий каталог остаются пустыми; устаревший результат не изображается действующей взаимностью; бумажный резерв показывает помощь организатора. Условные политики согласия различены по фазам запроса, ожидания, отказа, выдачи, изменения контакта и прекращения выдачи.

Обход функции рендера по всем 87 шагам подтвердил отсутствие неизвестных видов и контакта гостьи вне `contact`. Проверка экранирования входного HTML прошла. Проверку компоновки и всей галереи выполняет основной агент в браузере; это отдельная проверка от проверки функции.
