# Проверка интерактивных макетов перед показом

Принято по прямому требованию Сергея 08.10: «мы … согласовываем финальные макеты … глючит анимация … сделай так, чтобы ты мог находить такие ошибки» (P-028). Проверка JavaScript и fake DOM полезна для логики, но не подтверждает отрисовку, сенсорные события и анимацию.

## Обязательный порядок

1. Воспроизвести изменение в настоящем браузерном движке на локальной копии вымышленного стенда. Проверять затронутые экраны на 320×568, 390×844 и 430×932; для жестов использовать сенсорный ввод браузера, а не dispatchEvent.
2. Сохранить видео, снимки состояний, trace и кадры requestAnimationFrame. Просмотреть изображения/движение до публикации; независимая проверка читает результаты и ищет пропущенные случаи.
3. Для найденного сбоя получить падающий воспроизводимый прогон, исправить и повторить затронутые проверки. Проверять отмену, границу жеста, быстрые действия, высоту viewport и reduced motion, когда они относятся к изменению.
4. Перед выкладкой выполнить существующие syntax/verify и сверить статические файлы с проверенной копией. После выкладки проверить штатный статус размещения. В HANDOFF записывать раздельно браузерную проверку, публикацию и пользовательскую приёмку.

Если браузерный прогон или просмотр не выполнен, результат обозначается непроверенным визуально; нельзя выдавать fake DOM или успешный деплой за проверку финального макета. Восстановление инструмента/конкретный следующий шаг фиксируется явно. Пользовательская приёмка В1–В5 остаётся отдельной.

## Повторяемый прогон D02

```powershell
.\tools\run_visual_qa.ps1 -RunName current
.\tools\run_visual_qa.ps1 -RunName base-room -Mode gallery
node --check apps/miniapp/demo.js
node apps/miniapp/scenarios/verify.mjs
```

Скрипт использует установленный Playwright/Chromium, поднимает свой временный loopback HTTP-сервер только для apps/miniapp и завершает его вместе с прогоном. Не требует рабочего Python preview или подключения к Sites/Telegram/CRM. В этой Windows-среде браузерному процессу нужен одобренный выход из sandbox для локального HTTP; запрет не обходится альтернативным адресом. Нет установки пакетов, логина или изменения настроек безопасности.

Если runtime расположен иначе, передать `-NodeModulesPath` из load_workspace_dependencies и `-BrowsersPath` установленного Playwright. Ошибка запуска завершает проверку с ненулевым кодом. Ненулевой код тестов также блокирует объявление проверки пройденной.

Артефакты: `outputs/visual-qa/<RunName>/report.json`, мобильные PNG, `*-swipes.webm`, `*-trace.zip`, `*-like-frames.json`, `*-native-frames.json`, `*-touch-events.json`, `reduced-motion-frames.json`. Они исключены из Git и не отправляются в Site. Запись содержит только локальных вымышленных гостей; производственные данные/авторизацию в trace не сохранять.

После P-030 дополнительно проверяются красный крест/зелёное сердце, одинаковые фоны/рамки, отсутствие верхнего профиля и нижняя вкладка «Знакомства». Сохраняются keyboard-focus/after-close PNG и close-touch JSON с hit-test/событиями/состоянием диалога. На 320 проверяется пять быстрых инерционных прокруток с одним tap закрытия после каждой: обычный click иногда подавляется Chromium, поэтому одного спокойного tap недостаточно. После смены viewport runner ждёт фактическое восстановление visualViewport/высоты приложения. Полный итог W-015 — 57/57; конкретный report и независимый просмотр в HANDOFF.

В облачном Linux тот же runner запускается через `bash tools/run_cloud_qa.sh cloud-current`; для галереи — `bash tools/run_cloud_qa.sh cloud-base-room gallery-only`. Зависимости/Chromium готовит `bash tools/setup_cloud.sh`. Эти облачные команды подготовлены, но ещё не исполнены в облаке; локальный результат не заменяет первый прогон после переноса. Порядок — CLOUD_HANDOFF.md.

Тесты D02 проверяют границу и обе стороны настоящего свайпа с фото/описания, короткий жест, pointercancel, вертикальный жест, повтор, видимость кнопок и размер портрета, геометрию следующей карточки на кадрах, смену высоты во время жеста/вертикальной отмены, reduced motion и ошибки браузера. После P-029 проверка фото относительная: высота не меньше ширины, вместо прежних 140 px, которые пропускали широкую полосу. Дополнительно проверяются иконки/aria-label/44 px, длинное имя и 400 символов с уже выбранной реакцией, отсутствие вложенного скролла и выходов за карточку/viewport, Tab только активного гостя, native tap полного текста, достижимость его конца касанием, закрытие с сохранением карточки/фокуса и профиль через нижнее меню (верхняя иконка убрана P-030). Следующий гость в фикстуре имеет длинное описание: измеряется переход и между разными длинами текста. Кадровая проверка требует реальные отсчёты и нормирует изменения ширины/прозрачности на 16.7 ms: она ловит резкую смену масштаба, а не измеряет FPS физического телефона. Визуальный просмотр остаётся необходим: числовой тест высоты не понимает обрезанное лицо, а успешный touch не замечает голубую вспышку поверх модалки.

## Ограничения результатов

Эмуляция мобильного viewport и настоящих touch/pointer-событий в Chromium — браузерная проверка, а не тест физического iPhone/Android или WebKit. Производительность устройства, адресная строка реального Safari и Telegram WebView требуют отдельного мобильного прогона. Публикация использует проверенный статический исходник; автоматическая проверка приватного Site с пользовательским логином не выполняется.

Первое применение и доказательства найденных ошибок — актуальный HANDOFF (W-012).
