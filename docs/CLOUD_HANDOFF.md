## Запуск и проверки в Linux

Проверочная зависимость Playwright1.62.1 зафиксирована в package.json/package-lock.json; это dev tooling, у статического приложения нет нового runtime-фреймворка. Нужны Node.js с npm и Python3.11+. Для установки браузера/системных библиотек — штатная установка в setup среды:

```bash
bash tools/setup_cloud.sh
```

Она выполняет npm ci, playwright install --with-deps chromium,13 Python-тестов, синтаксис demo.js и verify галереи. Полный setup в облаке **ещё не запускался**; локально проверены Bash-синтаксис, соответствие lock и тесты. Сетевой доступ к пакетам/браузерам и необходимые права на зависимости настраиваются в самой облачной среде; не переносить Windows-исключения sandbox.

```bash
bash tools/run_cloud_qa.sh cloud-initial
bash tools/run_cloud_qa.sh cloud-base-room gallery-only
python tools/dev_server.py --port 8765
```

Последняя команда служит для просмотра через доступный механизм preview среды;127.0.0.1 облачного контейнера нельзя выдавать Сергею как внешнюю телефонную ссылку. Основной QA runner поднимает и завершает свой Node loopback HTTP сам.

Один и тот же tools/check_swipe_browser.cjs используется и локально, и в облаке. Проверяет actual Chromium/CDP touch, а не dispatchEvent: жесты/отмену, rAF геометрию, viewport/reduced motion, цвет/фон реакций, полный текст, Tab, навигацию и пять fling→один tap закрытия на320. После смены viewport тест ждёт фактическое восстановление высоты, не снимает замер посреди старого resize.

Последний локальный результат:57/57, failures=[], Chromium151.0.7922.34, три viewport320×568/390×844/430×932, независимый phone_qa разрешил публикацию. Доказывает локальную Chromium-эмуляцию, не исполнение в облаке и не физические iOS/Android/Telegram WebView. Артефакты — outputs/visual-qa/classic-release локально; небольшая доказательная копия — qa/local-classic-release в переносимом пакете. Числа не заменяют новый прогон после переноса/изменений. Видео/trace остаются локально и не включаются в лёгкий пакет.

## Как перенести

Итоговый пакет: outputs/pb-match-cloud-20261008-ready.zip. Проверенный состав и SHA256 каждого файла записаны внутри CLOUD_PACKAGE_MANIFEST.json; сборка — tools/export_cloud_handoff.ps1 -PackageName pb-match-cloud-20261008-ready.

По [официальной документации Codex Cloud](https://learn.chatgpt.com/docs/cloud) новая среда подготавливается для выбранных GitHub-репозиториев, затем проверяется и публикуется; доступы/сеть/зависимости настраиваются в среде. Рабочая локальная папка не подключается автоматически.

По P-033 выбран отдельный публичный `carpzerkalniy/pb-match`, основная ветка `main`; имя/место/приватность заново не спрашивать. При создании среды Codex Cloud выбрать этот репозиторий и подключить GitHub с правами записи, если будет предложена авторизация. Рабочая копия на компьютере должна иметь `origin=https://github.com/carpzerkalniy/pb-match.git`. При смене рабочего места сначала сохранить и отправить коммиты в GitHub, затем получить обновления той же ветки в другой рабочей копии; несохранённые/неотправленные правки автоматически туда не переходят. Перед продолжением облачной задачи выполнить `git fetch origin` и проверить выбранную ветку; при последовательной работе `git pull --ff-only` получает отправленный результат без автоматического merge. Отдельные одновременные задачи вести в разных ветках `codex/...`, затем объединять проверенные изменения. В GitHub публикуются apps/docs/contracts/tests/tools, зависимости и небольшая доказательная копия QA в qa/local-classic-release. Сырые outputs, node_modules, реальные .env/токены, общая память и исторические docs/sources остаются локально; опубликован только перечень источников docs/sources/README.md. Подготовленный ранее ZIP сохраняется как прежний снимок, актуальные изменения получать из GitHub. Не считать commit отдельного Sites checkout коммитом этого проекта.
