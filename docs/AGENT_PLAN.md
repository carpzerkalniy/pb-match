## 1. Кто за что отвечает

Одновременно работают максимум четыре участника: основной агент и три помощника. Проверяющий `qa` запущен для блока 01; исполнителей сервера и интерфейса запускаем по зависимостям.

| Роль | Ответственность | Граница записи |
|---|---|---|
| Координатор — основной агент | Общается с Сергеем, фиксирует решения, выдаёт блоки, проверяет передачу результатов, собирает приложение | Документы требований, журнал, HANDOFF, общие договорённости между частями |
| Сервер | Вход, членство, хранение, CRM, лайки, контакты, бот и права админа | Серверный код и согласованные изменения хранения |
| Интерфейс | Гостевые и административные экраны, связь с сервером, состояния ошибок | Рабочий интерфейс; demo остаётся самостоятельным макетом |
| Проверка | Независимо проверяет правила, доступы, сохранение данных, отказы и полный путь | Проверки и отчёт; исправления производственного кода возвращает автору |

Координатор сам проверяет отчёт проверяющего. Агент не принимает собственный блок. Один файл имеет одного текущего владельца. Изменение общей договорённости сначала проходит координатора, затем доводится до обоих исполнителей.

## 2. Как выглядит один блок

Перед запуском: ID, входные материалы, зависимость, одна цель, разрешённые файлы, ожидаемый результат и конкретная проверка. На выходе: изменения, чем проверены, результат, ограничения, следующий блок. Состояния: запланирован → выполняется → проверяется → принят; отдельно — требует ответа / возвращён на исправление.

Если блок содержит несколько независимо проверяемых результатов, перед выдачей делим его ещё мельче. Следующий зависимый блок запускаем только после приёмки предыдущего. Независимый может идти параллельно. При дефекте автор исправляет, проверяющий повторяет затронутые проверки. Непроверенное не объявляем готовым.

## 9. Связи и порядок

Основная цепочка: 01–06 → 07–10 → 11–15 → 16–20 → 21–23 → 24–26 → С6 → 27.

Параллельно: сверка состояния с обсуждением правил; изучение системы с согласованием независимых продуктовых вопросов; интерфейс с серверной реализацией после принятого контракта; проверки сразу за каждым готовым блоком. Полный путь не откладываем до конца — собираем при 15, затем расширяем при 20 и 22.

При передаче между агентами координатор передаёт утверждённые правила, принятый контракт, изменённые файлы и доказательства проверки. Сообщение «готово» без этих материалов блок не закрывает.

В каждом этапе координатор фиксирует результат и следующий шаг в HANDOFF, решения — в DECISIONS; требования и вопросы обновляет по прямым ответам. Исходные документы остаются в этом репозитории. Старые макеты и документы сохраняются.
